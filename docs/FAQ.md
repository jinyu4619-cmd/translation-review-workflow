# FAQ

## 1. 为什么采用宽审核标准？

因为本工作流的目标是筛出会影响阅读和理解的问题，而不是做母语润色级挑错。

## 2. 文件夹里只有图片，没有辅助文件，能不能开始？

可以。

这套流程允许审核人员先自行生成辅助配对清单，再继续审核，不要求业务方必须先把辅助文件准备好。

## 3. 什么情况下判定为未通过？

只要存在以下任意情况，即判定为`未通过`：

- 中文没翻译干净 / 其他语言残留
- 词语翻译错误
- 涉及目标语言国家的敏感或政治话题
- 其他已明显影响理解的问题

## 4. 什么情况下不判未通过？

仅存在以下问题时，按`通过`处理：

- 一词多义但当前译法可理解
- 轻微语法错误
- 表达不够自然但不明显影响阅读
- 其他可改可不改的建议项

## 5. 截图里的工具栏和软件界面算不算问题？

要分情况看：

- 如果只是无语言信息的边框、装饰、图标，不单独算问题
- 如果最终交付图里仍保留中文或其他非目标语言文字的工具栏、标签页、状态栏、按钮文案，就按`中文没翻译干净 / 其他语言残留`处理

## 6. 问题说明和修改意见怎么写？

- 两者都必须编号
- 两者必须一一对应
- 修改意见必须直接写成`原文 -> 建议改为`
- 不能只写“修改”“优化”“调整一下”

## 7. 未通过项里为什么要放领取人、模板名称和中外文图片？

因为未通过项不只是审核记录，还要方便后续分发、修改和回查。

这些信息至少能解决三件事：

- 谁来改
- 改的是哪张模板
- 对照哪张中文图和哪张外文图改

## 8. 最终到底交付什么？

每个语种最终只交付两类结果：

- `检验进度台账.xlsx`
- `未通过项.xlsx`

如果只是第 3 类建议项，不单独再交第三份文档。

## 9. 为什么允许少量英文存在？

在非英文模板中，软件名、产品名、常见缩写、国际通用术语等少量英文通常不影响理解，因此在宽审核标准下可接受。
