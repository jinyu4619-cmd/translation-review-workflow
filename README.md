# 多语言翻译核对工作流

本仓库用于沉淀一套可复用的多语言翻译核对方法，适用于脑图模板等图文内容的人工复审场景。

## 这个仓库解决什么问题

- 统一不同语种的审核口径
- 降低多轮审核中的重复劳动
- 固化问题记录方式和修改建议写法
- 让审核结果能直接交给修改人员执行

## 适合谁使用

- 模板翻译审核人员
- 复审或抽检人员
- 负责整理交付结果的同事
- 需要接手修改未通过项的同事

## 先记住这 3 件事

1. 只审核预览图中已明确标记为`审核通过`或`验收通过`，且台账状态仍为`未审核`的模板。
2. 以中文模板为基准，采用宽审核标准；只抓明显错翻、明显残留、明显敏感问题，不做母语润色级挑错。
3. 最终只交付两类结果：
   - `检验进度台账.xlsx`
   - `未通过项.xlsx`

## 3 分钟上手

1. 先读[快速开始](./docs/快速开始.md)，了解完整操作顺序。
2. 再读[审核标准与流程](./docs/审核标准与流程.md)，统一审核口径。
3. 准备待审核图片文件夹；如果文件夹里只有图片，也可以先自行生成辅助配对文件再审核。
4. 审核前先统计本次待审模板数量，并预估完成时间。
5. 按固定格式输出 Excel 结果。

## 你需要准备的输入

- 待审核图片文件夹
- 能确认审核范围的预览图或台账信息
- 中文模板图与目标语言模板图
- 可联网环境，用于存疑译法人工复审

## 最终交付内容

### 1. 检验进度台账.xlsx

至少建议包含以下信息：

- 序号
- 预览行号
- 中文图编号
- 外文图编号
- 模板名称
- 审核状态
- 问题分类
- 备注

### 2. 未通过项.xlsx

至少建议包含以下信息：

- 序号
- 领取人
- 模板名称
- 中文模板图
- 外文模板图
- 预览行号
- 中文图编号
- 外文图编号
- 审核结论
- 问题分类
- 问题说明
- 修改意见

其中：

- `问题说明`必须编号
- `修改意见`必须编号
- 两者必须一一对应
- `修改意见`必须直接写明`原文 -> 建议改为`

## 审核结论规则

- 出现`① 中文没翻译干净 / 其他语言残留`或`② 词语翻译错误`中的任意一类，判定为`未通过`
- 仅存在`③ 可改可不改，建议修改`时，判定为`通过`

## 目录说明

```text
translation-review-workflow/
├─ README.md
├─ CONTRIBUTING.md
├─ docs/
├─ examples/
├─ templates/
├─ scripts/
└─ outputs/
```

- `docs/`
  - 放流程、规则、FAQ 等文档
- `examples/`
  - 放脱敏后的最小示例数据
- `templates/`
  - 放交付用的 Excel 模板
- `scripts/`
  - 放配对、整理、导出、预览等辅助脚本
- `outputs/`
  - 放可公开的样例输出结果

## 当前建议补充顺序

1. 先补脱敏后的最小示例
2. 再补固定格式的 Excel 模板
3. 最后再整理可复用脚本
