# 模板翻译校对

对用户提供的本地文件夹执行模板翻译校对，并把最终的两个 Excel 结果表保存回同一个文件夹。

每次执行前都先阅读 [references/review-standards.md](references/review-standards.md)。
组装导出 JSON 前，再阅读 [references/output-schema.md](references/output-schema.md)。

## 当前文件夹规则

把用户提供的文件夹视为“某一个语种”的持续审核工作文件夹。

- 用户在每一批审核前，可能会重新替换当前批次的 PNG 图片集。
- 所以当前文件夹代表的是“本批次最新快照”，不是所有历史图片的永久归档。
- 用户现在会直接导出“本次需要审核”的模板图片给你，因此不要再依赖总览图去判断哪些模板已经审核通过。
- 文件夹里可以有总览图，但总览图只作为辅助理解，不再决定审核范围。
- `检验进度台账.xlsx` 和 `未通过项.xlsx` 才是历史记录。
- 只审核当前文件夹里能找到中文图和外文图的模板。
- 如果旧台账里有 `未审核` 项，但当前文件夹里已经找不到对应图片，就继续保留 `未审核`，不要强行给出审核结论。
- 每一条台账记录和每一条未通过记录，都要保留该语种自己的 `审核批次`，例如 `第1批`、`第2批`、`第3批`。
- 如果该语种此前没有任何台账记录，本次新进入台账的模板就是 `第1批`。
- 如果该语种已经有历史台账记录，本次新进入台账的模板就是该语种的下一批。
- 在正式细审前，必须先明确告诉用户：本次是该语种第几批审核，例如 `英文第2批审核`。

## 执行流程

1. 先确认用户给出的路径存在，并且是本地文件夹。
2. 先运行 `scripts/scan_review_folder.py <folder>`。
3. 优先看扫描结果里的单张模板图；如果文件夹里刚好有总览候选图，只把它当辅助参考，不要再用它筛选审核范围。
4. 根据扫描结果判断当前模式：
   - 没有历史台账：视为首次审核；
   - 有历史台账：视为后续批次审核。
5. 判断当前文件夹对应的语种，可结合文件夹名称、当前模板图内容和历史台账一起判断；如有总览图，只作为辅助参考。
6. 建立中文图和外文图的对应关系，当前文件夹里能配对出的模板就是本次待审候选。
7. 建立或更新台账：
   - 首次审核时：把当前文件夹中本次待审的模板加入该语种 `第1批` 台账，并标记为 `未审核`；
   - 后续审核时：读取旧台账，把当前文件夹中新出现、但台账里还没有的模板加入台账，并标记为该语种下一批的 `未审核`。
8. 本次进入审核范围的模板，必须同时满足：
   - 当前文件夹里可以找到本次所需的中文图和外文图；
   - 台账中状态为 `未审核`，或者是本次刚新增入台账的模板。
9. 对旧的 `未审核` 行，如果这次还能在当前文件夹找到对应图片，可以继续审核，但要保留它原本的 `审核批次`，不要改写成新批次。
10. 结合图片内容、图片顺序和文件名来配对，不要只靠奇偶编号判断。
11. 正式细审前，必须先告诉用户：
    - 本次是该语种第几批审核；
    - 本次需要审核的模板数量；
    - 预计完成时间。
12. 按 [references/review-standards.md](references/review-standards.md) 中的宽审核标准，以中文模板图为基准逐一审核。
13. 先给出首次检验结论，也就是当前模板的初判结果。
14. 对首次检验结果再做一轮自我复审，但复审仍然使用同一套宽审核标准，不要额外加严。
15. 复审时重点检查两类误判：
   - 本该 `通过` 却被误判为 `未通过`，
   - 本该 `未通过` 却被误判为 `通过`。
16. 只有在完成复审并确认首次检验结论正确后，才把本次实际审核完成的台账行，从 `未审核` 更新为最终的 `通过` 或 `未通过`。
17. 把历史未通过项保留在原顺序，把本次新增的未通过项继续追加在 `未通过项.xlsx` 对应旧记录的下方。
18. 按 [references/output-schema.md](references/output-schema.md) 组装完整 JSON。
19. 运行 `scripts/export_review_workbooks.py <json> <folder>` 导出两个最终 Excel 文件。
20. 导出 `未通过项.xlsx` 后，必须再自行检查一遍未通过表中的必填信息是否填写完整。
21. 重点检查是否存在空缺字段，例如：
    - `领取人`
    - `模板名称`
    - `审核批次`
    - `中文模板图`
    - `外文模板图`
    - `审核结论`
    - `问题分类`
    - `问题说明`
    - `修改意见`
22. 如果发现任何未填项、漏填项或明显缺失内容，必须自行重新补全，再重新导出或覆盖结果文件。
23. 只有在两个结果文件都检查无误后，才把它们作为最终交付结果保存回用户最初提供的同一个文件夹。

## 审核原则

- 以中文模板图为基准。
- 采用宽审核标准。
- 只重点拦截高影响问题，例如明显错翻、明显残留非目标语言、敏感或政治内容、明显影响阅读的问题。
- 一义多翻可以放宽，只要表达成立且不影响阅读即可。
- 在其他外语模板中，少量英文可以放宽，只要不影响阅读。
- 对每个模板的最终结论，都要在首次检验后再复审一轮，但复审不是提高标准，只是确认首次检验是否正确。
- 凡是模板画面中属于设计内容本身、并且承载语义或信息的文字，都必须检查，不仅限于正文主标题和分支文字。
- 这类文字包括但不限于：插画中的字、人物手持内容、对话框、气泡框、吊牌、标签、路牌、徽章、按钮样式字、手写字、角标、小字说明、图标旁说明、装饰元素中的可读文字等。
- 只要这些文字是模板内容的一部分，而不是截图软件本身残留的界面元素，就必须纳入翻译核对。
- 如果只是截图没裁干净，边缘残留少量中文编辑框、工具栏或软件界面，但不影响模板正文阅读，则按截图问题处理，不单独判未通过。
- 纯润色类、风格类建议，不要直接判未通过。

## 输出要求

- `检验进度台账.xlsx` 必须保留历史全部记录，并叠加本次结果。
- `未通过项.xlsx` 必须保留历史全部未通过记录，并把本次新增未通过项继续追加在历史记录下方。
- 如果同一个模板在后续批次里再次审核未通过，旧记录不要删除，新一批未通过记录继续按当前批次追加在下面。
- 每一条台账记录和每一条未通过记录，都必须带有原始 `审核批次`。
- `未通过项.xlsx` 中必须嵌入真实的中文模板图和外文模板图，不能只写图片编号。
- `未通过项.xlsx` 导出后必须再自行检查一遍所有必填字段是否完整，发现缺项必须先补全再交付。
- `问题说明` 和 `修改意见` 必须编号，并且一一对应。
- 每一条 `修改意见` 都要足够明确，直接写出 `原文 -> 建议改为`。

## 何时暂停并询问用户

只有在以下情况才暂停：

- 当前文件夹里没有本次可审核的模板图对；
- 当前文件夹缺少某个模板所需的外文图；
- 认真检查后仍然无法确定中文图和外文图的对应关系；
- 用户提供的文件夹信息不足，无法确定本次对应语种。

如果被阻塞，要明确告诉用户具体缺少什么。

## 附带脚本

### `scripts/scan_review_folder.py`

在每次执行最开始运行，用于扫描文件夹、识别模板图候选，并读取已有台账和未通过表。总览图如有，只作为辅助信息。

### `scripts/export_review_workbooks.py`

在已经组装好最终 JSON 后运行，用于导出最终的两个 Excel 文件。

## 常见触发方式

典型请求会像这样：

- `用 template-translation-review 检查这个文件夹：C:\...\English-Test`
- `用这个翻译校对工作流审核 C:\...\某语种文件夹`
- `对这个文件夹执行模板翻译校对，并把结果保存回原文件夹`

如果用户只提供了文件夹路径，而上下文已经明确是在做模板翻译校对，就直接使用这个技能。
